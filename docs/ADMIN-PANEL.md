# 管理面板

管理面板不是独立后台站点。
它是主站侧栏中的一组选项卡（`frontend/src/admin/`）。

使用运维或管理员账号登录 `/`。
左侧出现「系统管理」。
其中含控制台、扫描器、用户管理页面。
它与「用电分析」共用外壳、会话与样式。

它替代两代旧设计：

- 后端 embed 的 `internal/httpapi/admin.html`（需 SSH 隧道；视觉脱节；用全权 `ADMIN_TOKEN` 做门禁）
- 需输入 `?token=…` 才能进入的 `/admin` 独立入口

旧路径 `/admin/` 与 `/admin` 仍可用。

## 安全模型

安全共三层，全部在服务端。
前端判断仅控制侧栏是否显示入口，不是门禁。

**1. 角色分层**（`user_accounts.role`，迁移 `000012`）

| 角色 | 能力 |
|---|---|
| `user` | 侧栏无「系统管理」。直接调管理端点返回 403 |
| `operator` | 控制台、扫描器配置与控制、前端展示配置、查看用户列表、查看审计 |
| `admin` | 以上全部 + 改他人角色、启停账号、改系统凭证（邮件供应商） |

**2. 鉴权中间件**（`internal/httpapi/admin_auth.go`）

管理端点全部经 `adminAuth(required)`。
鉴权有两条通道：

- **用户会话**：`Authorization: Bearer <access token>`。
  角色每次请求查询数据库。
  在面板降权后，下一请求立即生效，无需等待 token 过期。
- **`ADMIN_TOKEN`**：供机器使用（CI、迁移脚本、健康探测），视同 `admin`。
  该令牌为全权，仅允许出现在服务器上。
  **禁止放入浏览器**。

401 与 403 含义不同：

- 401：未表明身份（前端跳转登录）
- 403：已表明身份但级别不足（显示无权）

**3. 会话控制**

复用用户端 refresh 轮换与复用检测。
禁用账号时吊销该账号全部会话。
面板另有「踢下线」：仅吊销会话，不禁用账号。

面板每次写入均记录一行 `admin_audit_log`：谁、何时、改了什么。
凭证类改动只记录字段名，不记录字段值。
审计日志本身可被读取。

## 第一个管理员（自举）

库中尚无 `admin` 时，会话通道无法进入。
使用服务器上的 `ADMIN_TOKEN` 提升一名用户：

```sh
curl -X POST http://127.0.0.1:8080/api/v1/admin/users/promote \
  -H "Authorization: Bearer $ADMIN_TOKEN" \
  -H 'Content-Type: application/json' \
  -d '{"email":"you@example.com","role":"admin"}'
```

该邮箱必须对应已注册账号。
之后在面板「用户」页改角色。

## 环境隔离

面板遵守三环境约定（`backend/docs/DEPLOYMENT.md` §0）：

| 变量 | 作用 |
|---|---|
| `VITE_ADMIN_PANEL` | 前端构建期开关。不为 `true` 时管理界面不编入产物，侧栏不出现「系统管理」。 |
| `SETTINGS_ENCRYPTION_KEY` | 后端。`system_settings` 中凭证列的 AES-256-GCM 密钥，32 字节 base64 或 hex。 |
| `APP_ENV` | 管理内容区顶部状态带的环境角标（DEV / TEST / PROD）由它决定。 |

管理界面为懒加载独立 chunk（约 64 KB）。
仅进入「系统管理」时下载。
主包中仅有 `src/lib/adminAccess.ts`：判断侧栏是否显示该组入口。

反向代理必须将 `/admin` 交给前端的 `index.html`（SPA 单入口，旧书签仍可进入）：

```caddy
your.domain {
    root * /srv/dist
    handle /api/* { reverse_proxy 127.0.0.1:8080 }
    handle /health/* { reverse_proxy 127.0.0.1:8080 }
    handle {
        try_files {path} /index.html
        file_server
    }
}
```

`/api/v1/admin/*` 由后端响应。
面板页面本身是静态产物。

如果对外入口屏蔽了 `/api/v1/admin/*`，公网面板无法取数。
当前测试环境如此。
CI 对外验收断言其返回 404。
可选方案：

- 放开这些路径（已有角色鉴权）
- 继续经隧道访问

## 生成加密密钥

```sh
openssl rand -base64 32
```

写入服务器 `.env` 的 `SETTINGS_ENCRYPTION_KEY=`。
然后重启 api 与 worker。

未配置该密钥时服务仍可启动。
面板可查看与修改非敏感设置。
保存凭证时返回 `412 secrets_unavailable`，界面写出原因。
**必须拒绝明文落库，禁止静默将 API key 写入数据库。**

密钥更换后，旧密文无法解密。
面板提示「库中有凭证但当前密钥无法解密」。
重新填写并保存即可覆盖。
禁止将「无法解密」显示为「未配置」。
后者会让人误以为为空，保存时覆盖真实凭证。

## 推送渠道：保存后立即生效

「推送渠道」页保存后立即生效，无需重启：

- 明文字段（供应商、发件人、站点地址）存 `system_settings.value`
- 凭证（Resend API Key / SMTP 密码 / 腾讯云 SecretKey）经 AES-GCM 加密后存 `secrets`
- 每次保存 `version + 1`；`mailer.Resolver` 发信前比对版本号，版本变化则按新凭证重建供应商
- 两者均缺省回落到环境变量。未在面板配置的部署行为不变

凭证三态必须前后端一致：

| 请求里的 `secrets.<field>` | 含义 |
|---|---|
| 字段缺席 | 保留库中原值（用户未改该栏） |
| `null` 或空串 | 清空，回落到环境变量 |
| 字符串 | 存为新值 |

读回时凭证仅返回打码值（`re_E9••••snE9`）与「是否已配置」布尔值。
面板将打码串显示在输入框。
用户未改时不会把圆点当作新密钥写回。
后端也会忽略含 `••` 的值。

保存后可在页面发测试邮件验证。
测试使用**服务端已保存**的配置。
改字段后必须先保存再测。

### 渠道分类

同一页可维护用户端渠道列表分组（`features.channel_categories`）。
分类只影响展示：

- 一个渠道最多属于一个分类。改归属时从旧分类移除。后端拒绝同一渠道归属多个分类。
- **组内顺序由「用户端渠道展示」的上移/下移决定**。分类只存成员名单，不存顺序。
- 未归入任何分类的渠道出现在用户端列表末尾的「其它渠道」。新接入渠道不会消失。
- 删除分类仅解散分组，不隐藏任何渠道。全部分类删除后，用户端退回平铺列表。

分类与三态、顺序共用一次「下发展示状态」提交。
请求为 `PUT /api/v1/admin/frontend-config`。

腾讯云 SES 的代码与配置项仍保留。
测试期因审核慢先使用 Resend。
切回时在下拉框更换供应商即可。

## 面板页面

| 页 | 内容 |
|---|---|
| 控制台 | 合格表数、worker 心跳、未确认异常、邮件是否可用。服务与排程状态。30 秒自刷新。 |
| 扫描器 | 余额、日明细、月账单三类任务。支持触发、历史、重试、终止。配置 cron / QPS / 并发 / 重试。保存后 worker 15 秒内热重载，安全上限仍由环境变量把关。 |
| 用户 | 搜索邮箱、昵称、电表号。查看会话数与验证状态。改角色、启停、踢下线、解绑、删号。 |
| 推送渠道 | 平台邮件供应商配置与测试发送。用户端渠道分类、顺序与三态。 |
| 前端展示 | 登录与注册开关。图表开关。站点名与电价。空房阈值。榜单时刻。校历。改后刷新生效。 |

**终止与 SCHEDULE 开关分工**（两件事，禁止混用）：

- `SCHEDULE ON → MANUAL ONLY` 仅停止**未来**定时触发。
  对已在运行的任务无影响。
  同时 worker 不再自动恢复该采集器中断的任务。
- 「终止」按钮停止**当前这一次**任务。
  点击后为异步：worker 下次心跳（15 秒内）才真正停止。
  在途电表会跑完当前块，不硬断连接。
  任务最终状态为 `已终止`。
- `已终止` 为终态。
  重启 worker 也不会续跑。
  `被中断` 会被自动恢复。
  要彻底停一个采集器：先终止当前任务，再将 SCHEDULE 拨到 MANUAL。

### 第三方登录（Google / GitHub）

「前端展示 · 登录与注册」页从上到下包含全部配置。
两个开关控制**入口是否显示**。
「第三方登录凭证」控制**是否可用**。
两者均为真时，登录页才绘制按钮。
未配置凭证的一侧开关为灰色，文案中写明缺项。

凭证在网页填写后立即生效。
无需改 `.env`，无需重启：

| 字段 | 含义 |
|---|---|
| 站点地址 | 用于拼接回调地址。留空则回落到 `.env` 的 `OAUTH_BASE_URL` / `PUBLIC_BASE_URL` |
| Client ID | 两家各一个，明文存储 |
| Client Secret | 两家各一个，AES-GCM 加密存储，读回仅为打码值 |

页面直接给出需粘贴到提供方后台的**回调地址**（带复制按钮）。
形如 `https://你的域名/api/v1/auth/oauth/google/callback`。
手抄该地址出错是常见失败原因，因此由服务端计算。

约定：

- 凭证与邮件供应商、人机验证同级。
  **仅 `admin` 可查看与修改**。
  `operator` 可改上方两个开关，看不到密钥。
- 存密钥要求已配置 `SETTINGS_ENCRYPTION_KEY`。
  否则输入框禁用（与「推送渠道」页相同）。
- 环境变量退化为**兜底**：面板留空的栏才使用 `.env`。
  已写在 `.env` 的部署无需改动。
  也可仅在面板补 GitHub，Google 仍走 `.env`。
- **仅填 ID 不填 Secret 时，保存接口返回 400**。
  写在 `.env` 中的同类错误会令服务启动失败。

同一**已验证**邮箱会关联到已有账号，不会新建账号。
邮箱未验证则既不关联也不建号。
由此注册的账号无密码。
改密码、换邮箱、注销前，必须先走「忘记密码」设置首个密码。
管理员也可用此路径登录。
面板门禁始终是账号角色，不是登录方式。

面板禁止自锁：

- 不能改自己的角色与状态
- 不能将最后一个活跃管理员降级或禁用（否则无人可进，只能改库）

### 人机验证失效时的运维救援

普通浏览器请求不会因 Turnstile 缺令牌、令牌过期或脚本加载失败而绕过验证。
令牌在页面停留过久时，前端会自动重置组件并获取新挑战。

若站点密钥失效或 Cloudflare 长时间不可达，运维可 SSH 到服务器执行：

```sh
bash ~/apps/edu-power-push/current/scripts/captcha_rescue.sh
```

脚本仅通过 `127.0.0.1` 调用管理 API，并从服务器 `.env` 读取机器专用
`ADMIN_TOKEN`。它只把 provider 切为 `disabled`，保留站点密钥、加密 secret
和受保护动作，便于登录面板修复后重新测试、启用。不要把 `ADMIN_TOKEN`
复制到浏览器或发送给其他人。

自动 push 部署不会主动开启人机验证。只有在 Actions 手动部署时明确勾选
“刷新 Turnstile 密钥并明确启用人机验证”，才会上传密钥并开启；已启用站点
在每次部署时都会做 Siteverify 探测，探测失败则自动走同一回环管理通道关闭验证。

## 入口：登录后侧栏出现

管理界面不是另一站点。
它是主站左侧多出的一组选项卡。
使用运维或管理员账号登录 `/` 后，侧栏出现「系统管理」。
普通账号看不到该组。
未登录也看不到。

旧书签 `/admin` 仍可用。
它将地址栏改回 `/` 并落在控制台页。
级别足够则进入。
级别不足则退回概览页。

旧入口暗号 `?token=…` 已删除。
原因与影响如下：

- 真正拦越权的是角色鉴权。
  每个 `/api/v1/admin/*` 仍要求 `operator` 及以上，且角色每次请求查库。
  暗号拦不住请求。
- 暗号增加运维成本。
  换设备或浏览器时，必须到服务器查找每次部署都会变化的随机字符。
- 站点是否有后台无法隐藏。
  登录页、接口路径、开源代码均可看出。
  门锁比门藏更可靠。

已删除内容：

- 后端 `GET /api/v1/admin/panel`
- 配置项 `ADMIN_PANEL_TOKEN`
- 部署脚本中每次发布轮换字符串的逻辑
- 权限 0600 的 `.admin-panel-path`

服务器 `.env` 中的遗留变量由下次部署自动清除。
